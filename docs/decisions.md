# 결정 사항

설계 검토(1~6차, 2026-11-18)와 구현 중(2026-11-18 ~ 11-20)에 내린 결정을 모은다. 각 항목은 **결정**과 **이유**를 함께 적는다.

관련 문서: [아키텍처](architecture.md) · [기능 명세](features.md)

---

## 1. 제품 범위

| #   | 항목         | 결정                                                                                  | 이유                                                                                                                 |
| --- | ------------ | ------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| Q1  | 자동 배정    | **하지 않는다.** 나이스 기본 편성을 손으로 조정하는 도구                              | 나이스에서 기본 편성(이름/생년월일순 또는 성적순)을 마쳐야 XLSX를 내려받을 수 있으므로 진급반이 항상 채워져 들어온다 |
| Q4  | 전입·전출 행 | **무시한다.** 가져오기·매핑·통계·내보내기 모두 제외하고 요약에 "무시한 행 n건"만 알림 | 전입은 진급 처리 후, 전출은 진급 전에 끝나므로 실제 데이터에는 나올 수 없다                                          |
| Q5  | 반 수 변경   | **불가.** XLSX 진급반코드 최댓값으로 고정, 반 추가·삭제 UI 없음                       | 인가 학급 수는 교육(지원)청이 정하고 입학 때 인가된 수가 3학년까지 유지된다                                          |
| Q6  | 작업 단위    | `.mix` 파일 1개 = 반편성 1건(1개 학년). 앱 내부 작업 목록 없음                        | 문서처럼 옮기고 백업하기 쉽다. 파일을 지우면 개인정보도 사라진다                                                     |
| Q8  | 메모 저장    | 작업 파일 안에 저장                                                                   | 파일을 옮기면 메모도 함께 옮겨진다                                                                                   |
| —   | 산출물       | 나이스 업로드용 XLSX **하나만**. 확인용/공지용 PDF 내보내기, 로그인, 광고 없음        | 로컬 데스크톱 앱이고 최종 목적은 나이스 업로드                                                                       |

## 2. 데이터 처리

| #   | 항목               | 결정                                                                                                                                          | 이유                                                                                                             |
| --- | ------------------ | --------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| —   | XLSX↔PDF 매핑 키   | 1순위 **(진급반, 진급반번호) + 정규화 성명**, 2순위 (이전반, 이전번호) + 성명(XLSX 내 유일할 때만), 3순위 성명 단독(유일할 때만, "확인 필요") | 샘플에서 이전학적이 겹치는 학생이 2쌍 있어 이전학적만 쓰면 2명이 잘못 연결된다. 1순위 키로는 231/231 정확히 매칭 |
| —   | 매핑 반영          | 자동으로 쓰지 않고 **매핑 검토 화면에서 [반영]** 해야 기록. 한 학생에 PDF 행 2개가 붙는 등 충돌은 반영 불가                                   | 성적은 편성 판단의 근거라 오매핑을 조용히 넘기면 안 된다                                                         |
| —   | PDF 파싱 방식      | 텍스트를 이어 붙인 정규식이 아니라 **pdf.js 좌표 기반 행·열 복원**                                                                            | PDF에서 긴 이름이 두 줄로 갈라져 정규식 파싱이 깨진다                                                            |
| Q9  | 동명이인 비교      | 공백을 모두 지우고 대소문자를 무시해 비교                                                                                                     | 한국 국적 학생은 한글 성명을 붙여 써 영향을 받지 않음. 외국인 학생의 로마자 대문자 성명 띄어쓰기 차이에 대비     |
| Q10 | 쌍둥이 후보 범위   | "유력"(생년월일+성 같음)과 "가능"(생년월일만 같음) 모두 표시, "가능"은 기본 체크 해제                                                         | 나이스 자료에 쌍둥이 필드가 없어 확정은 교사가 한다. 생일이 겹치는 우연이 흔하다                                 |
| —   | 기준성적 저장 형식 | **×100 정수**(0.01점 단위), 평균도 정수 반올림으로 계산                                                                                       | 부동소수 오차 없이 표시·비교하고 평균 차를 안정적으로 판정하기 위해(구현 중 결정, 커밋 48c16e5)                  |
| —   | 성비 지표          | 반별 \|남−여\| 의 최댓값, 4명부터 경고                                                                                                        | 한 반이 얼마나 치우쳤는지를 바로 보이게(구현 중 결정, 커밋 48c16e5)                                              |

## 3. 번호

| #   | 항목             | 결정                                                                                                                                                                   | 이유                                                                                                                                                                                                                                                                                                                                                                            |
| --- | ---------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Q3  | 반 내 번호 규칙  | **가나다순만** 지원(같으면 학번순). 정렬 기준은 `numbering.ts`의 함수 하나로 분리                                                                                      | 학교별 규칙(예: 남→여)을 나중에 넣을 수 있게                                                                                                                                                                                                                                                                                                                                    |
| —   | 가져온 직후 번호 | **나이스 번호 그대로** 둔다                                                                                                                                            | 나이스 번호가 단순 가나다순과 다른 곳이 있어(로마자 성명 위치 등) 가져올 때 다시 매기면 원본과 달라진다                                                                                                                                                                                                                                                                         |
| —   | 자동 재정렬      | 이동·바꾸기로 학생이 들어오거나 나간 반만 그 자리에서 가나다순 재정렬. 나머지는 [이 반/전체 재정렬]로                                                                  | 화면에 보이는 번호가 곧 내보낼 번호가 되도록                                                                                                                                                                                                                                                                                                                                    |
| —   | 번호 직접 수정   | 번호를 늘리면 그 학생 앞에 빈 번호가 생기고 뒤 학생이 밀린다. 줄이면 앞의 빈 번호를 지운다. 순서는 바꾸지 않는다                                                       | 전입생 자리를 남기는 실무 요구. 가나다 순서를 거스르는 번호는 만들지 않는다                                                                                                                                                                                                                                                                                                     |
| —   | 빈 번호 위치     | 예정 이름(있으면) 또는 만들 때 바로 앞 학생의 정렬 키를 기준으로 재정렬해도 제자리 유지. 반 끝에는 만들 수 없음                                                        | 기준 학생이 다른 반으로 가도 자리가 유지되어야 한다. 마지막 번호 뒤는 나이스가 다음 번호를 준다                                                                                                                                                                                                                                                                                 |
| —   | 가져온 결번      | 나이스 번호의 결번은 빈 번호(`origin='import'`)로 가져온다                                                                                                             | 재정렬해도 사라지지 않게                                                                                                                                                                                                                                                                                                                                                        |
| —   | 로마자 성명 정렬 | 교사가 입력한 **한글 표기**(`sort_name`, 성-이름 순, 원지음(原地音)·외래어 표기법 기준)로 가나다 정렬. 자동 음차 제안은 하지 않음. 표기가 없으면 한글 성명 뒤 알파벳순 | 학적업무요령상 외국인 학생 성명은 여권(외국인등록증, 외국인등록 사실증명)을 따르고, 로마자·한글 표기가 함께 있으면 보호자가 고른다. 로마자를 고르면 나이스 성명에 가나다 자리가 없어 한글 표기가 필요하다. 한글 표기는 원지음(原地音)을 따르는데(「외국인의 성명 표기에 관한 표준」 제6조제2항) 원지음은 출신국마다 달라 자동 제안은 틀리기 쉽다. 내보내는 성명은 바꾸지 않는다 |

## 4. 내보내기

| #   | 항목            | 결정                                                                                                                                       | 이유                                                    |
| --- | --------------- | ------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------- |
| Q2  | 진급반코드 형식 | 원본과 같은 **숫자형**(`5`, `05` 아님)                                                                                                     | 원본 양식과 형식이 달라지지 않게                        |
| —   | 쓰기 방식       | 가져온 원본 XLSX를 템플릿으로 열어 **진급반코드·진급반번호 셀만** 수정. 행 순서·학번 텍스트 형식·헤더 서식·열 너비·시트 이름·글꼴은 그대로 | 나이스가 거부할 여지를 최소화                           |
| —   | 전입·전출 행    | 출력 파일에서 행 삭제                                                                                                                      | 가져올 때 건너뛴 행. 실제 데이터에는 없다               |
| —   | 안전한 저장     | 임시 파일에 쓰고 → 다시 읽어 행 수·학번·값 일치 확인 → 대상 파일 교체                                                                      | 실패해도 기존 파일이 깨지지 않게                        |
| —   | 검증 단계       | ❌ 차단(번호 중복, 범위 밖 반), ⚠️ 경고(분리 위반, 인원 차, 매핑 미완료, 한글 표기 미입력), ℹ️ 안내(빈 번호, 변경 요약)                    | 경고는 교사 판단에 맡기고 나이스가 거부할 오류만 막는다 |

## 5. 작업 파일

| #   | 항목      | 결정                                                                                                          | 이유                                                                                                     |
| --- | --------- | ------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| Q11 | 확장자    | `.mix`(내용은 SQLite), 파일 연결 등록                                                                         | 더블클릭으로 열리는 문서처럼                                                                             |
| —   | 저장      | 저장 버튼 없이 즉시 트랜잭션 기록                                                                             | 저장하지 않아 작업을 잃는 일을 없앤다                                                                    |
| —   | 저널 모드 | `journal_mode=DELETE`(WAL 사용 안 함)                                                                         | `-wal`/`-shm` 파일이 생기면 USB·메일로 옮길 때 데이터가 빠질 수 있다                                     |
| —   | 원본 보관 | XLSX·PDF를 BLOB으로 파일 안에 보관                                                                            | `.mix` 하나만 옮겨도 내보내기 가능                                                                       |
| —   | 되돌리기  | 이력을 파일 안 `change_log`에 저장, 단계 제한 없음                                                            | 앱을 다시 켜도 되돌리기·이력 유지                                                                        |
| —   | 열기 실패 | 새 파일을 먼저 연 뒤 지금 파일을 닫는다                                                                       | 열기에 실패해도 하던 작업을 잃지 않게                                                                    |
| —   | 쓰기 방식 | 새 파일·사본·백업·설정은 임시 파일에 쓴 뒤 이름 바꾸기, DB 쓰기는 IMMEDIATE 트랜잭션 하나로(확인도 그 안에서) | 중간에 실패해도 기존 파일이나 절반만 바뀐 상태가 남지 않게, 확인과 쓰기 사이에 다른 쓰기가 끼어들지 않게 |

## 6. 암호화

| #   | 항목             | 결정                                                                    | 이유                                                                                                                            |
| --- | ---------------- | ----------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| —   | 적용 여부        | **선택 사항.** 파일 메뉴에서 비밀번호 설정·변경·해제                    | `.mix`에는 학생 개인정보가 들어가고 USB나 메일로 옮기기 쉽다. 다만 비밀번호를 잊으면 파일을 다시 열 수 없으므로 강제하지 않는다 |
| —   | 암호화 단위      | 파일 전체가 아니라 **민감한 칸만 값 단위로** AES-256-GCM                | 반·번호처럼 개인을 알 수 없는 값은 평문으로 두어 번호 중복 검사·정렬을 SQL에서 할 수 있게                                       |
| —   | 평문으로 두는 값 | ID·외래 키, 반·번호 자리, 성별, 종류·상태 값, 시각, 원본 파일 이름·해시 | 이름만으로는 개인을 알 수 없는 값                                                                                               |
| —   | 위치 묶기        | `표.열#행id`를 AAD로 사용                                               | 암호문을 다른 칸이나 다른 학생 행으로 옮기는 변조를 감지                                                                        |
| —   | 키 파생          | PBKDF2-HMAC-SHA256 600,000회, 반복 횟수는 파일마다 저장                 | OWASP 권장값. 나중에 기본값을 올려도 기존 파일이 열린다                                                                         |
| —   | 키 보관          | 파일을 연 동안만 메모리, 닫으면 지움. 비밀번호는 어디에도 저장하지 않음 | 설정 파일이나 OS에 비밀이 남지 않게                                                                                             |
| —   | 비밀번호 규칙    | 8자 이상, 공백만으로 된 비밀번호 불가                                   |                                                                                                                                 |
| —   | 평문 조각 정리   | `secure_delete` 항상 켬, 설정·해제·변경 후 `VACUUM`                     | 암호화하기 전의 평문 조각이 파일에 남지 않게                                                                                    |
| —   | 내보내기         | 나이스 업로드용 XLSX는 암호화하지 않음                                  | 나이스 양식 그대로여야 업로드된다                                                                                               |
